# Blazor / Razor component parameters

> Part of the [tag-library format prior-art deep-dive](overview.md). Field-by-field reference extracted from primary sources. **Framing:** observed on its own terms as industry practice — not mapped onto current WO/ng conventions.

**Role:** Code *is* the descriptor (no separate file)

**Artifact / file shape:** There is no separate descriptor file: the component's public API is declared inline in the C# of a `.razor` file (`@code { ... }` block) or its code-behind `.razor.cs` partial class. Each input is a public auto-property decorated with `[Parameter]` (or `[CascadingParameter]` / `[SupplyParameterFromQuery]`); each event is a `[Parameter]` of type `EventCallback`/`EventCallback<T>`; each slot is a `[Parameter]` of type `RenderFragment`/`RenderFragment<T>`. The Razor compiler reflects over these annotated members at build time to generate strongly-typed tag-binding code, and the runtime reflects over them again to set values via `ParameterView`. The component's tag name is its class name and its namespace is its 'library' identity; consumers bring it into scope with `@using`/`_Imports.razor`. Two-way binding, content templates and named slots are all expressed through naming conventions ({Param}Changed, {Param}Expression, ChildContent) layered on the same `[Parameter]` mechanism rather than as distinct schema fields.

## Fields

Every meaningful construct the format declares, at every level. *Use* = consumed by the IDE/tooling, the runtime, or both.

### `element/tag` level

| Field | Declares | Accepts | Req. | Use | Example |
|---|---|---|---|---|---|
| `[Parameter]` | Marks a public property of a component class as a component parameter — a typed input slot the parent supplies by writing an attribute on the component tag (<Child Title="...">). There is no separate descriptor file: the C# property + attribute IS the parameter declaration. The Razor compiler and runtime discover parameters by reflecting over [Parameter]-annotated properties. | Applied to a public auto-property of any CLR type (string, int, int?, user/value types, tuples, RenderFragment, EventCallback, etc.). AttributeUsage(AttributeTargets.Property, AllowMultiple=false, Inherited=true). sealed class ParameterAttribute : Attribute. | ✔ | both | `[Parameter] public string Title { get; set; } = "Set By Child";` |
| `route parameter ({param} in @page)` | Route-template parameters declared in the @page directive bind URL path segments to a matching [Parameter]. Not an attribute on the parameter itself — the @page route template plus a same-named [Parameter] together declare a path-sourced binding. Demonstrates multiple declarative value SOURCES (tag attribute, cascading, query, route) layered over the same [Parameter] mechanism. | @page "/route/{text}" route template + [Parameter] public string? Text {get;set;} matched by name. Constraints like {id:int} supported. | — | both | `@page "/route-parameter-1/{text}"  ...  [Parameter] public string? Text { get; set; }` |
| `component naming / namespace rule` | A component's tag name is its C# type name (PascalCase, must start uppercase) and its 'library' identity is its CLR namespace, derived from project root namespace + folder. There is no explicit library-descriptor field — namespace import (@using) governs which tags are in scope. This is how Razor namespaces and resolves component tags. | File ProductDetail.razor => <ProductDetail> tag in namespace derived from folder; brought into scope via @using or _Imports.razor. | ✔ | both | `@using BlazorSample.CustomEvents` |
| `[EventHandler] (custom DOM event registration)` | Class-level attribute registering a custom DOM event name and its EventArgs type so the Razor compiler recognizes a new @on{event} directive with IntelliSense and correct arg typing. Must live on a static class literally named 'EventHandlers' in a .cs file. Tooling-facing: teaches the compiler/IDE about an event, while JS-side registration handles runtime. Shows a separable 'event vocabulary' descriptor distinct from the component. | [EventHandler("oncustomevent", typeof(CustomEventArgs), enableStopPropagation: true, enablePreventDefault: true)] on `public static class EventHandlers {}`. | — | both | `[EventHandler("oncustompaste", typeof(CustomPasteEventArgs), enableStopPropagation: true, enablePreventDefault: true)]` |

### `attribute/prop` level

| Field | Declares | Accepts | Req. | Use | Example |
|---|---|---|---|---|---|
| `public auto-property requirement` | Structural rule: component parameters MUST be automatically-implemented properties (no custom get/set logic) and MUST be public. The framework sets them via reflection through ParameterView.SetParameterProperties; private/protected parameters are not externally settable. | `public T Name { get; set; }` — both accessors auto-implemented. Initializers allowed for defaults. | ✔ | both | `[Parameter] public DateTime StartDate { get; set; } = DateTime.Now;` |
| `ParameterAttribute.CaptureUnmatchedValues` | Boolean flag on [Parameter] that turns ONE parameter into a catch-all sink for every tag attribute that does not match a declared parameter (attribute splatting / passthrough). The component forwards them to an inner element or child component via @attributes. DIRECT analogue to a passthrough/splat flag. At most one parameter per component may set it true. | bool (default false). Decorated property type MUST be usable with RenderTreeBuilder.AddMultipleAttributes — i.e. IEnumerable<KeyValuePair<string,object>>, in practice Dictionary<string,object> (string-keyed). | — | both | `[Parameter(CaptureUnmatchedValues = true)] public Dictionary<string, object>? AdditionalAttributes { get; set; }` |
| `[EditorRequired]` | Marks a [Parameter] as required so EDITORS and BUILD TOOLS emit a warning (RZ2012) when the consumer omits the attribute. The required-binding analogue. Explicitly NOT a runtime guarantee: not enforced at runtime, does not guarantee non-null. Microsoft directs you to use this INSTEAD of C#'s `required` modifier or `init` accessor on parameter properties. | Marker attribute (no value). Valid only on a property also marked [Parameter]. Available ASP.NET Core 6.0+. EditorRequiredAttribute. | — | both | `[Parameter, EditorRequired] public string? Title { get; set; }` |
| `{PARAMETER NAME}Changed convention` | Naming convention that makes a parameter two-way-bindable. If a component has parameter Value plus an EventCallback<T> named ValueChanged (parameter name + literal 'Changed' suffix), the consumer can write @bind-Value="x" and Razor expands it to Value="x" + ValueChanged="@(v => x = v)". DIRECT pull/push directionality analogue — the pair (Value, ValueChanged) declares a bidirectional binding. The compiler enforces the name pairing. | A [Parameter] of type T named {Name} PLUS a [Parameter] EventCallback<T> named {Name}Changed. Convention-based, resolved by the Razor compiler (not a discrete attribute). | cond. | both | `[Parameter] public int Year { get; set; } [Parameter] public EventCallback<int> YearChanged { get; set; }  // <ChildBind @bind-Year="year" />` |
| `{FIELD OR PROPERTY NAME}Expression convention` | Optional companion to two-way binding: a parameter named {Name}Expression of type Expression<Func<T>> captures the EXPRESSION TREE of the bound field/property, not just its value — letting the component recover the model object and field name (via FieldIdentifier.Create). Used to build validation components that need to know WHICH field is bound. Razor auto-supplies it from @bind-{Name}. | [Parameter] public Expression<Func<T>> {Name}Expression { get; set; } — convention-based, compiler-supplied. | — | both | `[Parameter] public Expression<Func<int>> YearExpression { get; set; } = default!;` |
| `@bind / @bind-{PROPERTY}` | Consumer-side directive attribute establishing two-way binding. @bind="field" on an HTML element; @bind-{Property}="field" on a component binds to that component's named two-way parameter (e.g. @bind-Year). Compiler-expanded into a get of the parameter + a set wired to the matching {Property}Changed callback. Case-sensitive: @bind valid, @Bind/@BIND invalid. | Razor directive attribute; value is a C# field/property/expression. {PROPERTY} placeholder names a two-way-capable component parameter. | — | both | `<ChildBind @bind-Year="year" />` |
| `@bind:get / @bind:set (and @bind-{PROPERTY}:get / :set)` | Explicit two-way binding modifiers (NET 7+). :get supplies the value to bind; :set names a callback invoked when the value changes. Lets the consumer intercept/transform a value BEFORE it is applied (unlike post-hoc DOM-event binding). Microsoft now RECOMMENDS :get/:set over hand-writing the Value/ValueChanged pair for cross-component binding, avoiding the awkward Task-discarding setter pattern. | Razor directive-attribute modifiers. :get takes a field/property; :set takes a delegate/lambda (sync or async). Used as a pair. | — | both | `<input @bind:get="inputValue" @bind:set="HandleValueChange" />` |
| `@bind:event` | Modifier selecting WHICH DOM event triggers the binding update for element binding: oninput (every keystroke) vs onchange (default, on commit/blur). For component binding, @bind-{PROPERTY}:event names the change callback (defaults to {PROPERTY}Changed). Controls granularity/timing of the push half of the binding. | Razor modifier; value is an event name string ('oninput' \| 'onchange') for elements, or the callback name for components. | — | both | `<input @bind="InputValue" @bind:event="oninput" />` |
| `@bind:after` | Modifier specifying a delegate to run AFTER the bound value has been assigned (e.g. trigger a search once the model updates). Notable constraint: you may NOT pass an EventCallback/EventCallback<T> to @bind:after — only a method returning Action or Task. Works for both element and component (@bind-{PROPERTY}:after) binding. | Razor modifier; value is a C# delegate returning Action or Task (sync or async). Not EventCallback. | — | both | `<input @bind="searchText" @bind:after="PerformSearch" />` |
| `@bind:format` | Element-binding modifier supplying a single DateTime format string used to render and parse the bound value. Currently limited to DateTime; number/currency formats explicitly not yet supported (documented as a possible future addition). | Razor modifier; value is a .NET DateTime format string. | — | both | `<input @bind="startDate" @bind:format="yyyy-MM-dd" />` |
| `[CascadingParameter]` | Marks a property whose value is supplied implicitly by the nearest ancestor <CascadingValue> in the render tree, rather than written as an attribute by the immediate parent. Context/ambient-value injection that flows down the hierarchy and bypasses intermediate components. Distinct from [Parameter]: set from ancestor context, not from the tag. | sealed class CascadingParameterAttribute : CascadingParameterAttributeBase. AttributeUsage(AttributeTargets.Property, AllowMultiple=false, Inherited=true). Property of a type compatible with the cascading value. | — | RT | `[CascadingParameter] public ThemeInfo Theme { get; set; }` |
| `CascadingParameterAttribute.Name` | Optional name disambiguating WHICH cascading value to receive. If set, the value comes from the closest ancestor CascadingValue<T> supplying a value with this Name. If null (default), matching is purely by compatible TYPE. Allows multiple cascading values of the same type to coexist, selected by name. | string (nullable). Null => match by type only. | — | RT | `[CascadingParameter(Name = "ParentCount")] public int CountFromParent { get; set; }` |
| `[SupplyParameterFromQuery]` | Marks a [Parameter] of a routable component to be populated from the current URL query string, and re-populated when the query string changes. A declarative source-binding (value origin = URL query) rather than parent-supplied. Implemented as a cascading-parameter subtype (inherits CascadingParameterAttributeBase). | sealed class SupplyParameterFromQueryAttribute : CascadingParameterAttributeBase. AttributeUsage(AttributeTargets.Property, AllowMultiple=false, Inherited=true). Available 6.0+. Applied alongside [Parameter] on a routable/page component. | — | RT | `[Parameter, SupplyParameterFromQuery] public int Page { get; set; }` |
| `SupplyParameterFromQueryAttribute.Name` | Optional name of the query-string key to read. If null (default), the query parameter is assumed to share the same name as the property — i.e. property name IS the key unless overridden. Decouples the public URL key from the C# property name. | string (nullable). Null => use the property name as the query key. | — | RT | `[SupplyParameterFromQuery(Name = "q")] public string? SearchTerm { get; set; }` |

| Field | Declares | Accepts | Req. | Use | Example |
|---|---|---|---|---|---|

### `event` level

| Field | Declares | Accepts | Req. | Use | Example |
|---|---|---|---|---|---|
| `EventCallback` | The non-generic action/event binding type. A [Parameter] of type EventCallback exposes an outbound event the parent wires a handler to (<Child OnClick="Handler">). Weakly typed: InvokeAsync(object) accepts any argument. Invoking it automatically calls StateHasChanged on the parent — the framework handles re-render, unlike a bare delegate. Used when no value is passed. | Microsoft.AspNetCore.Components.EventCallback (a readonly struct, not a delegate type). Permits async delegates. Invoked via InvokeAsync(). | — | both | `[Parameter] public EventCallback OnSubmit { get; set; }` |
| `EventCallback<TValue>` | Strongly-typed action/event binding. Preferred over non-generic EventCallback because it gives better compile-time/IDE error feedback when a wrong handler type is bound. InvokeAsync(T) requires a T assignable to TValue. The building block of two-way binding (see {Param}Changed convention). | Microsoft.AspNetCore.Components.EventCallback<TValue>. Struct. Async delegates permitted. | — | both | `[Parameter] public EventCallback<MouseEventArgs> OnClickCallback { get; set; }` |

## Multi-library / composition

There is no library/namespace field in any descriptor — 'library' identity is the component's CLR namespace (project root namespace + folder), and resolution is governed by C# `@using` directives (per-file or globally via `_Imports.razor`). Two components with the same short name in different namespaces are disambiguated by which `@using` is in scope, or by writing the fully-qualified tag. External-package components become available by adding the package reference plus an `@using`. Conflicts (two like-named tags both in scope) surface as Razor compiler ambiguity errors. This piggybacks entirely on the host language's namespace/assembly system rather than inventing a tag-library registry, manifest, prefix or alias scheme — there is no per-library version, prefix, or alias field.

## What a greenfield ng/WO format should take from this

Several mechanisms are worth adopting. (1) CaptureUnmatchedValues is an exemplary passthrough design: a single boolean on ONE parameter declaring it the catch-all sink for unmatched attributes, with an explicit 'at most one per component' rule and a typed shape (string-keyed map) — a clean, well-bounded splat a new format should copy almost verbatim. (2) The (Value, ValueChanged) two-way convention plus explicit `:get`/`:set` modifiers is a strong pull/push model: the value half and the push half are SEPARATELY addressable, and `:get`/`:set` let the consumer intercept a change BEFORE it is applied — superior to bindings that only notify after the fact. Worth stealing that two-way is sugar over a value+event pair; but a greenfield format should make the pairing an explicit descriptor field rather than a stringly-typed '+Changed' suffix (the convention is fragile and invisible to the uninitiated). (3) EditorRequired cleanly separates tooling-time required-ness (a warning, IDE+build) from a runtime guarantee — the docs are emphatic it does NOT enforce at runtime. Keep that separation, but a modern format should ALSO offer a real runtime/required contract, since EditorRequired's lack of teeth is a documented weakness. (4) RenderFragment<T> as a typed, parameterized slot (content that receives a value) is a better slot model than untyped child-content holes — support both default and named, typed slots. (5) Pluralized value SOURCES over one uniform parameter mechanism (tag attribute vs cascading/ambient vs URL query vs route segment) is elegant: the parameter declaration is one thing, and WHERE its value comes from is an orthogonal declarative annotation — a separation a new tag-library format would benefit from. What it does poorly: nearly everything is convention-by-naming-suffix ({Name}Changed, {Name}Expression, ChildContent), invisible, unenforceable except by the compiler, and impossible to introspect from a manifest — a descriptor-first format should make these explicit, named fields.

## Documented pitfall / regret

Documented regrets/sharp edges: (1) EditorRequired is explicitly NOT enforced at runtime and does not guarantee a non-null value — and the docs warn AGAINST using C#'s natural `required` modifier or `init` accessor on parameters, forcing a weaker tooling-only attribute instead. (2) The 'avoid overwriting parameters' rule: a component must not write to its own [Parameter] properties after first render or framework re-supply silently clobbers them — a recurring footgun with its own dedicated docs page. (3) Two-way binding across more than two components before .NET 7 required an awkward pattern of discarding the Task returned by EventCallback.InvokeAsync inside a property setter; `@bind:get`/`@bind:set` were added specifically to fix this, an acknowledgment the original Value/ValueChanged-only model was insufficient. (4) @bind:after cannot take an EventCallback — a non-obvious carve-out. (5) Directive casing is rigidly case-sensitive (@bind valid, @Bind/@BIND invalid), a common trap.
